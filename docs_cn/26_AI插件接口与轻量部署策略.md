# AI 插件接口与轻量部署策略

> 日期：2026-05-28  
> 结论：PackVision 基础包不内置 YOLO、SAM、Depth Anything 等重模型；先提供插件发现、依赖体检和能力声明接口。现场需要时，再单独安装模型插件包。

## 1. 新增接口

```text
GET /api/ai/plugins
```

它会返回：

- 当前是否安装 AI 插件。
- 插件目录是否存在。
- 插件支持哪些能力，例如检测、OBB、分割、人工复核辅助、手机照片深度先验。
- 模型文件是否缺失。
- 运行依赖是否缺失，例如 `onnxruntime`。
- 基础包兜底链路：深度相机、OpenCV、人工框、复核样本池。

## 2. 插件目录

默认目录：

```text
D:\Documents\包装尺寸检测\models
```

现场安装目录：

```text
%LOCALAPPDATA%\PackVision\models
```

也可以用环境变量覆盖：

```powershell
$env:PACKVISION_AI_MODEL_ROOT="D:\PackVisionModels"
```

## 3. 插件结构

```text
models/
  packvision-yolo/
    plugin.json
    weights/
      model.onnx
  segmentation/
    plugin.json
  depth-prior/
    plugin.json
```

`plugin.json` 示例：

```json
{
  "id": "packvision-yolo-carton",
  "name": "PackVision carton detector",
  "version": "0.1.0",
  "enabled": true,
  "engine": "onnxruntime_cpu",
  "capabilities": ["box_detection", "oriented_box_detection"],
  "runtime_dependencies": ["onnxruntime"],
  "model_files": [
    { "path": "weights/model.onnx", "required": true }
  ],
  "priority": "assist",
  "description": "Optional detector for cartons and long parts."
}
```

## 4. 为什么先做接口，不直接上模型

原因很现实：

1. 海外仓电脑通常没有强显卡。
2. EXE 和传输包要尽量小，最好控制在 100 MB 内。
3. 没有真实仓库数据集前，直接塞通用模型不一定更准。
4. 模型失败时必须能回退到深度相机、OpenCV 和人工复核。
5. AI 输出只能辅助，不能覆盖深度相机实测和真值验收。

## 5. 推荐能力分层

| 插件能力 | 作用 | 是否进入基础包 |
| --- | --- | --- |
| `box_detection` | 纸箱/包装检测 | 否 |
| `oriented_box_detection` | 长条件、斜放件 OBB | 否 |
| `segmentation` | 异形件轮廓辅助 | 否 |
| `manual_review_assist` | 复核时点选贴边 | 否 |
| `phone_depth_prior` | 手机照片相对深度辅助 | 否 |
| `capture_quality_assist` | 光照/反光风险辅助 | 可选 |

基础包继续保留：

- 深度相机测量。
- OpenCV ArUco/轮廓。
- 手动修正框。
- 复核样本池。

## 6. 交付策略

基础交付包：

```text
PackVision.exe
START_HERE.txt
check_astra_depth_status.ps1
docs_cn
```

AI 插件包单独交付：

```text
PackVisionModels.zip
models/<plugin-id>/plugin.json
models/<plugin-id>/weights/model.onnx
```

这样普通仓库先跑通基础测量；后续样本积累够了，再按仓库或国家单独下发模型插件。
