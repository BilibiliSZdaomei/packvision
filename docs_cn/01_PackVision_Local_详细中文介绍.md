# PackVision Local 详细中文介绍

## 项目定位

PackVision Local 是一个本地运行的包装尺寸检测 MVP。它面向仓库、打包台、跨境物流、售后配件发货等场景，目标是在暂时没有工业相机或深度相机的情况下，先用普通手机照片完成“可追溯、可复核、可扩展”的尺寸检测流程。

它不是只做一个 UI 原型，而是已经具备完整闭环：

- 本地 EXE 启动服务。
- 浏览器打开本地工作台。
- 上传图片。
- 后端调用 OpenCV 识别参考标记和包裹轮廓。
- 返回尺寸、置信度、质量标记和标注图。
- 后续可接入相机、扫码枪、电子秤、订单系统。

## 技术架构

当前版本采用轻量路线：

- 后端：`FastAPI`
- 图像算法：`OpenCV + ArUco`
- 前端：原生 HTML/CSS/JavaScript
- 打包：`PyInstaller` 单文件 EXE
- 数据存储：本地 `data/` 或 `%LOCALAPPDATA%/PackVision`

选择这条路线的原因：

- 比 Electron 更轻。
- Windows 上部署门槛低。
- 后端接口天然可复用，未来手机端、相机端、扫码端都可以调用同一套 API。
- OpenCV 生态成熟，后续升级到相机标定、透视校正、深度相机都比较顺。

## 核心接口

### `GET /`

打开本地 UI 工作台。

### `GET /api/health`

检查服务是否正常，返回版本和 OpenCV ArUco 能力。

### `GET /api/calibration-card.svg`

生成可打印 A4 校准卡。当前默认使用 50 mm ArUco 标记。

### `POST /api/measure`

图片测量接口。

表单字段：

- `top_image`：顶部照片，必填。
- `side_image`：侧面照片，可选。
- `marker_size_mm`：ArUco 标记实际边长，默认 50 mm。
- `manual_height_mm`：人工输入高度，可选。

返回内容：

- `status`：测量状态。
- `confidence`：置信度。
- `dimensions`：长、宽、高、体积。
- `quality_flags`：质量提示，例如是否检测到标记、是否缺高度、是否使用人工高度。
- `top_view` / `side_view`：图片尺寸、标记信息、标注图链接。
- `method`：测量方法说明。

## 当前测量逻辑

首版使用“参考标记 + 单目照片”的方式：

1. 用户打印 ArUco 校准卡。
2. 拍摄顶部照片时，把 ArUco 标记放在与包裹底面相同的平面。
3. 后端识别 ArUco 标记，得到像素到毫米的换算比例。
4. 后端提取包裹轮廓，计算旋转最小外接矩形。
5. 将矩形像素尺寸换算成毫米，得到长和宽。
6. 高度来自侧面图估算或人工输入。
7. 输出标注图，便于人工复核。

## 为什么普通手机照片不能直接稳定测三维

普通单摄照片缺少真实深度信息。只凭一张任意角度照片，很难稳定恢复包裹的长、宽、高，原因包括：

- 透视变形。
- 镜头畸变。
- 包裹边缘不清晰。
- 拍摄角度不固定。
- 参考物和包裹不在同一平面会造成比例错误。

所以首版采用诚实可控的策略：

- 顶视图测长宽。
- 侧视图或人工输入补高度。
- 输出质量提示，而不是伪造“绝对准确”的结果。

已有功能：

- 图片上传区。

- 顶部照片和侧面照片。
- 标记尺寸输入。

- 打开标注图。

## 当前局限

当前版本是 MVP，不是商业量方设备替代品。

主要局限：

- 对拍摄角度敏感。
- 对背景、光照、包裹边缘清晰度敏感。
- 高度需要侧面照片或人工输入。
- 轮廓识别对复杂包装、反光包装、软包裹不一定稳定。
- 暂无条码、订单号、重量、批量记录。

## 建议的下一步

按价值排序：

1. 增加“拍照规范引导图”：告诉用户标记怎么放、相机怎么拿。
2. 增加手动四角校正：轮廓识别失败时让用户点选包裹四角。
3. 增加批量记录表：订单号、图片、尺寸、体积、备注。
4. 增加扫码枪输入：绑定运单号或 SKU。
5. 增加称重字段：形成尺寸 + 重量记录。
6. 增加相机实时采集：USB 摄像头或工业相机。
7. 增加相机标定：减少镜头畸变带来的误差。
8. 增加深度相机版本：用于商业化自动量方。
