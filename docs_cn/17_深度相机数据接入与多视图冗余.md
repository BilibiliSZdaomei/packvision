# PackVision 深度相机数据接入与多视图冗余方案

## 当前已落地

PackVision 已经从“上传深度帧测量”升级为“可连接真实 Astra Pro 深度相机”的接口结构：

- 设备配置文件：`D:\app\orbbec-astra-pro\packvision-depth-cameras.json`
- 厂商 OpenNI 运行库：`D:\app\orbbec-astra-pro\viewer`
- Astra Pro 当前验证机位：`astra-pro-top-01` + `astra-pro-front-01`
- 当前验证角色：`top` + `front`
- 默认采集后端：`openni2_primesense`

项目不把相机写死在业务逻辑里，而是通过 `camera_id` 和 `role` 连接硬件、机位和测量结果。

> 2026-05-28 现场双相机首验：当前电脑已把两台 Astra Pro 配成 `top` 和 `front`，并写入 `serial_hint`。OpenNI 采集后端不再用 `open_all()` 同时打开所有设备，而是先枚举 URI、再只打开目标 `serial_hint` 对应的设备，避免双相机状态下厂商运行库 access violation。
>
> 2026-05-28 实时工位接入：`/api/depth/live/start` 在不指定 `role` 时按配置顺序采样整个相机 rig。当前现场验证结果是 `top` 可稳定测量，`front` 可返回真实 `640x480` 深度帧；即使正面视角暂时没有前景，也会保留 `camera_capture` 证据，UI 不再把已接入镜头显示成空白待接入。

## 数据连接接口

### 1. 查看相机拓扑

`GET /api/depth/cameras`

用途：

- 查看当前配置了几台相机
- 查看每台相机的 `camera_id`、`role`、OpenNI runtime
- 查看是否已经检测到 OpenNI 设备
- 查看三视图还缺哪些机位

### 2. 探测采集链路

`POST /api/depth/capture/probe`

示例：

```json
{
  "backend": "auto",
  "camera_id": "astra-pro-top-01",
  "role": "top",
  "timeout_ms": 1500
}
```

无相机时应返回 `openni_runtime_ready_no_device`，表示软件栈可初始化，但 USB 设备未连接。

相机连接成功后应返回 `ready_for_capture`。

接口还会返回 `field_diagnosis`，用于现场 UI 和体检脚本显示人话提示。重点字段：

- `severity`：`ready`、`waiting_for_camera`、`validation_required`、`action_required` 或 `blocked`。
- `operator_summary_key`：多语言 UI 的诊断文案键。
- `primary_actions`：按顺序列出现场动作，例如插 Astra Pro、打开 OrbbecViewer、重新探测、采集深度帧。
- `evidence.device_count`：OpenNI 当前看到的设备数。
- `can_continue_photo_fallback`：相机未就绪时，是否可先走照片兜底演练业务闭环。

### 3. 采集单帧深度数据

`POST /api/depth/capture/frame`

示例：

```json
{
  "backend": "auto",
  "camera_id": "astra-pro-top-01",
  "include_frame": false
}
```

`include_frame=false` 用于快速检查元数据，不返回完整深度矩阵。

`include_frame=true` 会返回 `depth_frame`，可直接进入 `/api/depth/measure-roi` 或 `/api/depth/measure-object`。

### 4. 采集并直接测量

`POST /api/depth/measure-capture`

用于现场业务主流程：从指定相机采集一帧，然后优先用深度帧自动识别前景 ROI，进行 ROI 或异形件掩膜测量，并进入原有历史记录和调用次数统计链路。

默认 `measurement_mode=object_mask`，更适合汽车备件异形件。

2026-05-28 起，测量成功后默认保存深度证据：下采样点云 `.npz` 和深度预览 `.png`。如果深度前景不足，接口会回退到中心作业区，并在 `capture_regions.reason` 中写明原因。

### 4.1 实时采集工作站

实时工作站不是“按按钮才开始检测”。它的主流程是：

```text
POST /api/depth/live/start
GET /api/depth/live/state
POST /api/depth/live/confirm
POST /api/depth/live/stop
```

- `start`：启动后台实时循环，持续采集深度帧并判断是否有稳定物体。
- `state`：返回当前状态，例如 `waiting_for_object`、`measuring`、`stable_ready`、`needs_review`。
- `confirm`：只负责把当前稳定候选绑定单号并保存到历史，同时写入点云 `.npz` 和深度预览 `.png`。
- `stop`：暂停实时循环。

相机到货前，实时循环可以使用模拟 Astra 深度帧干跑 UI、历史、统计和复核链路；相机到货后切换到真实 OpenNI/Astra Pro 后端。

### 5. 多视角结果融合

`POST /api/depth/fuse-measurements`

用途：

- 单相机时可作为统一出口，返回 `single_view_fallback`
- 两相机时可做顶视图 + 侧视图交叉校验
- 三相机时可做顶视图 + 前视图 + 左/右视图融合

默认策略是 `conservative_max`：长、宽、高都取可信视角中的保守最大值，避免仓库计费和物流装箱时低估尺寸。

## 为什么这样设计

仓库现场不能要求员工懂相机内参、焦距、标定矩阵，所以系统必须做到：

- 相机参数从配置、厂商 runtime、ROS camera_info 或工程师导入文件中来
- 员工只看到“连接相机、扫描单号、放件、测量”
- 后续换更贵的深度相机，只新增 backend 或更新配置，不重写测量 API
- 后续增加三台相机，只增加配置中的 camera entry，不改变业务主流程

## 当前 Astra Pro 适配状态

已适配：

- Windows Orbbec 驱动安装检测
- OpenNI runtime 初始化
- OpenNI 设备枚举
- OpenNI 单帧深度采集入口
- 默认 Astra Pro 深度 FOV 估算内参
- ROI 测量
- 异形件 object-mask 测量
- 多视角尺寸融合
- 测量历史、单号、后台调用次数统计复用

待相机到货后现场验证：

- `device_count` 是否变为 1
- 单帧深度矩阵是否稳定
- 实测纸箱、长条件、异形件的误差范围
- 是否需要导入厂商/ROS camera_info 替换 FOV 估算内参

## 三相机冗余建议

第一阶段：

- `top`：顶视图，负责长度、宽度和异形件平面轮廓

第二阶段：

- `front`：前视图，负责高度和遮挡校验

第三阶段：

- `left` 或 `right`：侧视图，负责长条件、保险杠、弯曲件的侧向轮廓补偿

配置示意：

```json
{
  "camera_id": "astra-pro-front-01",
  "role": "front",
  "enabled": true,
  "backend": "openni2_primesense",
  "model": "Orbbec Astra Pro",
  "serial_hint": "填写首次验证后识别到的设备 URI 片段"
}
```

## 现场验收顺序

1. 用 `D:\app\orbbec-astra-pro\启动上位机.bat` 打开 OrbbecViewer。
2. 确认 Color 和 Depth 都有画面。
3. 执行 `D:\app\orbbec-astra-pro\检查Astra安装.ps1`。
4. 调用 `/api/depth/capture/probe`，确认 `ready_for_capture`。
5. 调用 `/api/depth/capture/frame`，先用 `include_frame=false` 看元数据。
6. 用已知尺寸纸箱跑 `/api/depth/measure-capture`。
7. 保存历史记录，形成第一批误差验证数据。
