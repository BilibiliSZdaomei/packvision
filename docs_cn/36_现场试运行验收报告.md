# PackVision 现场试运行验收报告

> 日期：2026-05-28  
> 目标：让每台仓库电脑都能导出一份“当前是否可试运行、缺什么、下一步做什么”的证据报告。

## 1. 为什么要做这份报告

现场试运行不能只看“程序能打开”。专业 DWS 尺寸采集软件至少要同时证明：

- 本地程序和网页 UI 能启动。
- Astra Pro 驱动、官方上位机和 OpenNI 运行库已准备好。
- 实时监控正在工作，按钮只负责记录稳定结果。
- 测量记录能保存到历史库，并能追溯单号、尺寸和计费重。
- 电子秤未接入时有手动实重兜底，接入后能读取自动重量。
- 失败、低置信、异常材质和人工修正样本会进入复核池。
- WMS/TMS 接口没配置时也不会丢数据，本地 outbox 可以导出和重试。

这份报告就是把这些证据合成一个结论，方便现场验收、老板汇报和远程排错。

## 2. 接口

JSON 报告：

```text
GET /api/deployment/field-trial-report
```

Markdown 报告：

```text
GET /api/deployment/field-trial-report.md
```

## 3. 报告结论怎么读

| 状态 | 含义 |
| --- | --- |
| `needs_attention` | 基础运行条件还有阻断项，先处理环境问题。 |
| `pre_hardware_ready` | 相机到货前的软件、驱动、上位机、模拟实时链路已准备好，但真实精度还没验。 |
| `sample_collection_needed` | 运行链路可用，但还需要保存现场真值样本。 |
| `field_trial_ready` | 已具备现场试运行证据，可以继续按样本库做精度验收。 |

当前没有真实 Astra Pro 接入时，报告应当停在 `pre_hardware_ready`，不能写成真实硬件已验收。

## 4. 报告包含哪些证据

- `readiness`：开箱即用体检摘要。
- `station`：实时工位状态、专业 DWS 分数、当前候选尺寸、生产缺口。
- `latest_records`：最近几条历史记录。
- `review`：复核样本池摘要。
- `usage`：后台调用次数、测量次数、失败次数。
- `scale`：电子秤或手动实重状态。
- `integration`：WMS/TMS 本地队列、HTTP 推送器和重试状态。

## 5. 现场使用方式

1. 启动 PackVision。
2. 打开数据中心里的“验收报告”。
3. 点击“刷新报告”。
4. 如果需要发给老板或远程工程师，点击“导出 Markdown”。
5. 真实相机到货后，先用 OrbbecViewer 验深度画面，再重新刷新报告。

## 6. 和现场支持包的区别

| 项目 | 用途 |
| --- | --- |
| 现场试运行报告 | 给人看的结论和证据摘要，适合汇报和验收。 |
| 现场支持包 | 给工程师排错的 zip，包含 JSON、CSV、日志和真值模板。 |

两者应该一起使用：报告说明“现在差什么”，支持包帮助定位“为什么差”。
