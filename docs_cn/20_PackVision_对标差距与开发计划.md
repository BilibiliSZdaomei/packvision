## 1. 我给自己的目标模式

PackVision 后续开发按这个模式推进：

1. **仓库员工零选择优先**：一线员工只需要扫单号、放件、拍照或点击测量。包装类型、材质风险、测量模式优先由系统自动判断，人工选择只放在高级复核里。
2. **先业务闭环，再算法炫技**：单号、历史、日志、导出、异常复核、现场验收，比单个模型指标更重要。没有追溯能力的“测量成功”不算落地。
3. **默认轻量离线，重模型插件化**：主程序保持 CPU 可跑、普通电脑可用、EXE 尽量轻。YOLO、SAM、Depth Anything、ONNX 等能力做成可选插件，不强塞进基础包。
4. **深度相机是主线，手机照片是兜底**：手机单目照片只能做估算和预检；真实尺寸闭环要以 Astra Pro 深度帧、相机内参、深度质量门控、现场真值验证为准。
5. **每个功能都有四件套**：API 能跑、UI 能用、测试能过、中文文档能让仓库/老板看懂。
6. **不隐藏不确定性**：凡是模拟数据、单目估算、未硬件验证、反光/透明/黑色材质风险，都要在结果中明示置信度和复核建议。

一句话：**我后续会按“现场可用的小步交付”推进，而不是按“堆模型名词”推进。**

## 3. 还没做到或还不够强的地方

| 缺口 | 风险 | 后续动作 |
| --- | --- | --- |
| 还没有真实 Astra Pro 硬件验证 | 现在的深度测量主要靠模拟帧和算法单测，不能承诺现场精度。 | 相机到货后跑驱动、上位机、OpenNI/ROS、PackVision 四层验收。 |
| 没有真实仓库数据集 | 对异形件、黑色件、反光件、软包件的鲁棒性没有足够样本。 | 建立现场样本库：RGB 图、深度图、人工真值、单号、材质标签。 |
| UI 还需要继续降复杂度 | 工业现场不适合太多选项，员工没时间理解参数。 | 默认自动测量；高级参数折叠；把结果分成“可入库/需复核/失败重拍”。 |
| 部署仍依赖驱动和运行时 | 深度相机无法完全靠 EXE 解决，Windows 仍需要驱动/运行库。 | 做一键环境检查器和部署包清单，能自动提示缺什么。 |
| AI 模型还没有真实插件包 | 插件协议已完成，但还没有基于真实仓库样本训练/导出的模型。 | 等复核样本池积累后，再按仓库场景做 YOLO/分割/深度先验插件。 |
| 标定与内参链路还需要现场化 | 已能读取/归一化内参，但还没有真实相机 camera_info 验证。 | 优先使用厂商工具和 ROS/OpenNI 输出；仓库员工不手动输入内参。 |
| 多相机三视图还未真实联调 | 已有外参验收接口，但未做真实支架、时间同步和硬件验证。 | 到货后先两台相机 top/front，再扩展到 top/front/side。 |
| 缺少工业级异常恢复 | USB 断连、相机被占用、驱动异常、权限问题需要更友好的提示。 | 增加设备健康页、重连流程、现场排错二维码/文档。 |

## 5. 我们已经做得比较好的地方

1. **比通用视觉项目更贴近仓库业务**：高星项目通常只解决检测、分割、点云或标注中的一段；PackVision 已经把单号、历史、日志、导出、计费重、材质风险串起来。
2. **默认部署目标更现实**：我们一直把普通 Windows 电脑、无强显卡、低学历员工、跨国家仓库、多语言作为约束，而不是实验室环境。
3. **深度相机接入方向是对的**：手机照片不能稳定还原真实三维尺寸，Astra Pro 深度帧 + 内参 + 质量门控是更适合落地的主线。
4. **已经为三视图做了冗余设计**：后面买更好的相机或增加到三台，不需要推翻历史记录、行业规则和 API 结构。
5. **有汇报与管理口径**：后台调用次数、测量次数、CSV 导出，对以后向老板汇报使用量和节省人工有价值。

## 6. 对标不足的地方

1. **数据集不足**：高星 AI 项目强在海量数据和模型训练流程，我们现在缺真实汽车备件包装样本。
2. **硬件工程不足**：RealSense/Open3D 这类项目的设备管理、点云调试、多相机工具链比我们成熟很多。
3. **标注复核不足**：CVAT/Label Studio 把数据标注和质量复核做成体系，我们现在只有历史记录，还没把失败样本变成训练资产。
4. **UI 工业感还要继续打磨**：当前 UI 已简化，但还应继续向“扫码枪工作台”靠拢，而不是“参数表单工具”。
5. **安装器还不够完整**：真正发给其他国家仓库时，需要驱动检查、运行时检查、相机连接测试、更新机制、日志打包。
6. **精度标准还没落地**：没有真实硬件和真值样本前，不能正式定义“标准纸箱误差多少、异形件误差多少、失败率多少”。

## 7. 开发路线图

### P0：当前基础闭环，已完成大部分

目标：让项目在没有相机时也能演示和验证业务闭环。

- 图片上传测量。
- 顶部/侧面照片。
- 手动修正框。
- 单号、扫码、条码图片识别。
- 历史记录和 CSV 导出。
- 使用次数统计。
- 多语言主题。
- Astra Pro 无硬件模拟、深度 API、质量门控。
- 中文文档和 Obsidian 笔记。

验收状态：**基本完成**。

### P1：Astra Pro 到货后的第一轮硬件验收

目标：证明真实相机可以被公司电脑稳定识别，并能输出 PackVision 可用的深度帧和内参。

- 用厂商驱动和工具确认彩色流、深度流、D2C、点云能工作。
- 读取 ROS/OpenNI/camera_info 或厂商标定 YAML，走 `/api/depth/camera-info/normalize`。
- 跑 `/api/depth/capture/probe` 和 `/api/depth/capture/frame`。
- 用 5 个标准纸箱、5 个长条件、5 个异形件、5 个异常材质样本做第一轮真值对比。
- 保存所有记录到历史库，导出 CSV。

验收标准：

- 相机连续采集 30 分钟不崩溃。
- 100 次测量接口不出现程序级崩溃。
- 标准纸箱初步误差目标：单边中位误差不超过 10 mm 或 2%。
- 异形/软包/异常材质允许进入“需复核”，但不能无提示地给出高置信错误结果。

### P2：工业现场 UI 和部署包

目标：让仓库员工不需要懂参数也能使用。

- 首页只保留“扫码/单号、相机状态、开始测量、结果、复核”五块。
- 自动识别包装模式，不要求员工选择普通件/异形件/长条件。
- 结果统一分为：`可入库`、`需复核`、`重拍/失败`。
- 做部署检查器：驱动、OpenNI/SDK、USB、相机占用、数据库目录、日志目录。**已完成 readiness 接口第一版。**
- 做日志打包按钮：方便远程排错。**已完成现场支持包 API 和 UI 入口第一版。**
- 输出轻量版包和深度相机版包。

验收标准：

- 新电脑部署时，能在 10 分钟内跑到相机状态页。
- 普通员工只看中文界面也能完成扫码和测量。
- 没有相机时能清楚提示缺少什么，而不是直接报错。

### P3：真实样本库和复核闭环

目标：把每一次失败都变成后续训练和优化资产。

- 每条记录保存 RGB 图、深度图、标注图、测量结果、人工真值。
- 增加“复核样本池”：失败、低置信、材质异常、人工改框的记录自动进入复核。
- 设计 WPS/Excel 样本模板，方便仓库手填真值。
- 支持导出 YOLO/分割训练所需的基础数据结构。
- 建立标准纸箱、长条件、异形件、反光/透明/黑色/软包的最低样本量要求。

验收标准：

- 每次现场试运行都能导出“误差报告 + 样本清单”。
- 失败样本能追溯到原图、单号、员工操作、接口日志。
- 具备训练第一版包装检测模型的数据基础。

### P4：AI 插件化增强

目标：在不拖累基础包的前提下，引入 YOLO/分割/单目深度辅助。

- 设计模型插件目录：`models/packvision-yolo/`、`models/segmentation/`、`models/depth-prior/`。
- 已提供 `/api/ai/plugins` 插件发现和体检接口。
- 优先支持 ONNX Runtime CPU 推理，GPU/TensorRT 作为高级选项。
- YOLO/OBB 用于标准包装、长条件、异形件外接框。
- SAM 或轻量分割模型用于人工复核时快速贴边。
- Depth Anything 类模型只用于手机照片的相对深度辅助，不承诺毫米级尺寸。
- UI 中清楚显示“AI 辅助”和“深度相机实测”的区别。

验收标准：

- 不安装模型插件时，基础 EXE 正常可用。**已满足协议层验收。**
- 安装模型插件后，普通电脑仍能在可接受时间内完成单张推理。
- 模型输出失败时能回退到深度/手动框选流程。

### P5：多相机三视图和更高端深度相机

目标：支持未来两台、三台甚至更高端深度相机的扩展。

- 相机角色固定为 `top`、`front`、`side`，设备序列号可配置。
- 增加外参标定/验证流程，避免多视图尺寸互相矛盾。
- 已提供 `/api/depth/extrinsics/validate` 检查角色、序列号、外参和已知纸箱视角冲突。
- 融合策略先保守：取可解释的最大包络尺寸，并报告视角差异。
- 支持未来新增相机后端，不改历史记录和 UI 主流程。
- 为长条件和大件建立更适合三视图的测量策略。

验收标准：

- 两台相机可同时接入并稳定采集。
- 三视图测量出现明显冲突时，系统自动标记复核。**协议层已支持，待硬件验证。**
- 新相机只新增 backend/provider，不重写业务 API。

4. **真值样本模板增强**：让 WPS/Excel 模板可以直接记录纸箱、长条件、异形件、异常材质。
5. **失败样本池设计**：基础接口、UI 和真值模板已完成，下一步优化现场复核填写体验和样本资产导出格式。
6. **模型插件接口设计**：协议层已完成，下一步等真实样本后做小模型插件包或实验分支。
7. **三视图外参方案**：协议和文档已完成，下一步等相机到货后用固定支架和已知纸箱实测。

## 9. 对老板/现场能讲清楚的版本

PackVision 不只是“拍照量尺寸”。它的定位应该是：

> 给海外汽车备件仓库用的本地测量工作台。员工扫码后放件，系统自动调用手机图片、深度相机或多相机方案测量尺寸，保存历史、标注图、单号、使用次数和误差报告。普通包装自动过，异形件和异常材质自动进入复核。基础版轻量离线可用，深度相机版用于提升精度，AI 模型作为后续插件增强。

这个定位比单纯追求某个视觉模型更稳，因为它直接服务仓库里的实际流程：**少填参数、少培训、可追溯、能汇报、能持续变准。**
