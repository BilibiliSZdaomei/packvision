# 多相机外参与三视图验收方案

> 日期：2026-05-28  
> 目标：为两台/三台 Astra Pro 或未来更高端深度相机准备外参、角色绑定、视角冲突和保守融合验收链路。

## 1. 新增接口

```text
POST /api/depth/extrinsics/validate
```

用途：

- 检查相机角色是否齐全：`top`、`front`、`side`。
- 检查多相机是否绑定序列号。
- 检查非参考相机是否录入外参：平移、旋转或 4x4 变换矩阵。
- 用同一个已知纸箱的多视角测量结果做冲突判断。
- 冲突时进入 `review`，不自动给高置信通过。
- 融合策略继续使用 `conservative_max`，避免低报包装尺寸。

## 2. 角色命名

现场说法和代码说法统一如下：

| 现场说法 | API 角色 | 说明 |
| --- | --- | --- |
| 俯拍相机 | `top` | 第一台相机，默认参考坐标。 |
| 正面相机 | `front` | 第二台相机，用于高度和正面轮廓交叉验证。 |
| 侧面相机 | `side` / `left` / `right` | 第三台相机，任一侧向角色都视为 side。 |

仓库员工不需要理解外参。工程人员只需要在现场安装时给相机贴标签，例如：

```text
TOP-01
FRONT-01
SIDE-01
```

## 4. 状态含义

| 状态 | 含义 | 现场动作 |
| --- | --- | --- |
| `ready` | 角色、外参、序列号和已知样本冲突检查都通过。 | 可以进入现场试运行。 |
| `needs_attention` | 缺少侧向相机、缺少重叠样本等非阻断问题。 | 可单相机/双相机继续验证，但不要宣称三视图完成。 |
| `review` | 多视角测量冲突超阈值。 | 固定支架、重新采集已知纸箱、检查外参。 |
| `blocked` | 缺少 front/top、缺少关键外参、序列号重复等阻断问题。 | 先处理硬件和配置。 |

## 5. 到货后验收顺序

1. 单台直连电脑，先用 OrbbecViewer 验证 RGB/Depth/IR/点云。
2. 在 PackVision 中跑单台 `/api/depth/capture/probe`。
3. 给每台相机贴角色和序列号。
4. 固定支架，尽量不要再移动。
5. 录入或测量外参。
6. 用已知尺寸纸箱在三视图下各测一次。
7. 调用 `/api/depth/extrinsics/validate`。
8. 如果返回 `review` 或 `blocked`，不要进入正式测量。

## 6. 为什么用保守融合

汽车备件仓库最怕尺寸低报，因为低报会影响运费、仓储和包装预估。

所以多视角结果融合默认：

```text
conservative_max
```

也就是每个维度取可解释的最大值，并保留每个视角的来源。如果视角差异超过阈值，系统进入复核，而不是悄悄平均掉误差。
