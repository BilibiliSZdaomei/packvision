# PackVision 开发方向二次审计与高星项目差距

> 日期：2026-05-28  
> 分支：`codex/astra-pro-depth-camera`  
> 审计目的：核对 Astra Pro 厂商资料包、当前 PackVision 实现和 GitHub 高星视觉/深度/标注项目，判断开发方向是否有遗漏、误判或需要立刻纠偏的地方。

## 1. 结论先说

PackVision 的大方向是对的：**不要把手机单目照片当成最终精度来源，真实落地应以 Astra Pro 深度相机、相机内参、深度质量门控、历史追溯和真值复核为主线**。

但现在确实有几个需要正视的开发失误风险：

1. **自动测量还不够自动**：当前 `/api/depth/measure-capture` 在没有 ROI 时会使用中心作业区，这是比 0 结果好，但它不是工业级自动找箱子。仓库员工不该选择 ROI，系统必须从深度/RGB 中自动找前景、找桌面、找最大可测物体。
2. **相机参数链路还不完整**：项目已经能归一化 `camera_info`，但还没有把厂商/ROS/OpenNI 的真实 `get_camera_params`、设备序列号、SDK 版本、深度比例、流配置完整写入每条测量记录。
3. **点云能力还停留在轻量算法层**：现有深度测量主要是 ROI/mask 投影和主轴范围，距离 Open3D/RealSense 那类项目的点云调试、平面分割、OBB、配准和可视化还有明显差距。
4. **厂商标定板要被纳入主流程，而不是继续用旧校准卡做主入口**：A4 ArUco 可以作为手机照片兜底比例尺，但 Astra Pro 主链路应优先使用厂商工具、ROS/OpenNI 的内参和厂商棋盘格。
5. **复核样本池有了，但训练数据资产还没形成**：失败样本、低置信样本、人工改框记录还需要能导出成 YOLO/COCO/OBB、点云样本和真值报告，才能真正对标 CVAT、Label Studio、Ultralytics 的数据闭环。
6. **多相机目前是架构预留，不是实测能力**：已有角色、序列号、外参校验接口，但还缺真实支架、同步、外参估计、USB 压力和三视图冲突验证。
7. **UI 仍要继续向“扫码工作站”收敛**：工作台应该只暴露扫码/单号、相机状态、自动测量、结果、复核建议；历史、统计、工程参数、标定工具不应占据主工作界面。

一句话判断：**项目不是走偏了，但现在最危险的地方是把“中心 ROI + 模拟深度帧”误认为“自动工业测量”。下一步要把自动分割、点云 OBB、真实内参和样本闭环做实。**

## 1.1 本轮已落地的纠偏增量

2026-05-28 已完成第一步代码纠偏：

- `/api/depth/measure-capture` 在未传 ROI 时，会先根据深度帧自动估计桌面深度、提取离桌面更近的最大前景组件，并生成 `auto_depth_foreground` ROI。
- 如果深度前景不足或画面不可判断，才回退到 `auto_center_default` 中心作业区，并在 `capture_regions.reason` 写明原因。
- 测量成功后默认保存深度证据：下采样点云 `.npz` 和深度预览 `.png`，结果中返回 `depth_evidence`、`artifacts.depth_point_cloud_url`、`artifacts.depth_preview_url`。
- 复核样本池会带上 `depth_point_cloud` 链接，低置信和异常样本后续能追溯到点云证据。
- `/api/depth/measure-capture` 已纳入后台测量次数统计。

这只是把“中心 ROI Demo”推进到“深度前景自动测量首版”，还没有完成 Open3D 级别的平面分割、OBB 可视化和真实相机参数链。

## 4. 我们做得比通用项目更贴近业务的地方

1. **有仓库业务闭环**：单号、条码、历史、时间戳、使用次数、CSV、支持包，比单纯视觉 Demo 更接近现场。
2. **有轻量部署意识**：基础包不内置 YOLO/SAM/Depth 大模型，适合普通 Windows 办公电脑。
3. **承认手机照片的边界**：没有把 EXIF/焦距估算包装成高精度能力，方向上是诚实的。
4. **已经预留深度相机和多相机接口**：后续买更贵相机时，不必推翻业务 API 和数据结构。
5. **有中文资料和 Obsidian 知识网络**：便于给老板、仓库和后续维护人员讲清楚。

这些是 PackVision 的优势，不能为了追模型热点把它们丢掉。

## 5. 目前最需要补的五条主线

### P0：Astra Pro 真实参数链

目标：每一次深度测量都能说清楚“这台相机是谁、用的什么内参、什么流配置、什么深度比例、什么 SDK/驱动状态”。

要做：

- 从厂商工具、OpenNI 或 ROS 输出中导入 `camera_info` / `get_camera_params`。
- 记录设备序列号、SDK 版本、彩色/深度分辨率、FPS、深度单位、内参来源。
- 把这些元数据随测量记录保存，支持后续追责和误差分析。
- 厂商棋盘格用于工程验收和必要重标定，旧 A4 ArUco 只作为手机图片兜底比例尺。

### P1：真正自动找物体

目标：仓库员工只扫码、放件、点击测量，系统自己判断箱子/长条/异形件/异常材质。

要做：

- 深度帧自动前景提取：去桌面、去背景、去无效深度、保留最大稳定组件。
- RGB 辅助轮廓：当深度边界不清晰时，用颜色/边缘辅助找外接区域。
- 自动判断普通箱、长条件、异形件、软包、反光/透明/黑色风险。
- 低置信时进入复核，而不是输出 0 或高置信错误值。

### P2：点云 OBB 和证据保存

目标：不是只给长宽高数字，还能保存工程证据，方便解释为什么这么量。

要做：

- 每次深度测量保存下采样点云：`NPZ` 或 `PCD`。
- 保存点云预览图、深度质量图、mask 图、测量 OBB。
- 先用轻量 NumPy/OpenCV 实现可用版本，再把 Open3D 做成可选调试插件。
- 对规则纸箱用平面/箱体模型，对异形件用保守包络尺寸。

### P3：真值样本和训练数据闭环

目标：每一次失败都能变成后续优化资产。

要做：

- 复核样本池导出 COCO/YOLO/OBB、CSV、原图、标注图、深度样本。
- 建立最小样本清单：标准箱、长条、软包、异形、黑色、反光、透明、遮挡、贴胶带。
- 支持人工真值录入后生成误差报告：中位误差、P90 误差、失败率、复核率。
- 为未来 YOLO/分割/OBB 插件准备训练数据格式。

### P4：现场工作站 UI

目标：普通仓库员工不需要懂“深度相机工作区、历史、统计、复核、标定参数”这些工程概念。

要做：

- 主工作台只保留：单号/扫码、相机状态、自动测量、结果、操作建议。
- 历史和统计放到“数据中心”页面。
- 复核放到“复核队列”页面，并用明确状态解释：为什么要复核、谁来复核、复核后保存到哪里。
- 标定和相机参数放到“工程/维护”页面，默认隐藏。
- 结果用三段式表达：`可入库`、`需复核`、`重拍/失败`。

### P5：多相机外参和稳定性

目标：未来两台/三台深度相机不是简单拼接口，而是可验证、可复现。

要做：

- 固定角色：`top`、`front`、`side`，绑定序列号。
- 设计外参验收：棋盘格/AprilTag/已知纸箱，多视角测量互相校验。
- 记录时间戳、帧延迟、USB 带宽、供电状态。
- 三视图冲突时保守融合，并进入复核队列。

## 6. 这次审计判断出来的“不要做错”的点

1. **不要把旧 A4 ArUco 校准卡当 Astra Pro 主标定工具**。它只能兜底手机图，Astra Pro 应优先厂商/ROS/OpenNI 内参。
2. **不要让员工选择普通件/异形件/长条件**。现场没有时间，系统应自动判断，判断不了就复核。
3. **不要把单目深度模型当真实尺寸来源**。Depth Anything/MiDaS 可以辅助理解照片，但没有绝对尺度闭环。
4. **不要只保存结果数字**。必须保存原始证据、标注、元数据、版本、内参和真值，后续才能解释误差。
5. **不要一开始把大模型打进 EXE**。普通电脑、跨国仓库、100MB 交付包都不适合这么做。
6. **不要把多相机当 UI 选项**。多相机是硬件工程，需要支架、同步、外参、USB 和样本验证。

## 7. 下一轮开发建议

优先级按现场风险排序：

1. **把 `/api/depth/measure-capture` 从中心 ROI 升级为自动找物体**：深度前景、桌面去除、最大组件、低置信复核。
2. **把真实相机参数链路补完整**：导入/记录 `camera_info`、`get_camera_params`、序列号、SDK、流配置。
3. **新增点云证据保存接口**：深度测量同时保存下采样点云、mask、质量图、OBB 预览。
4. **整理厂商棋盘格主入口**：UI 和文档中明确厂商棋盘格用于 Astra Pro 工程验收，A4 ArUco 用于手机照片兜底。
5. **复核样本池导出训练格式**：先做轻量的 COCO/YOLO/CSV，再考虑 YOLO/ONNX 插件。
6. **重构工作台信息架构**：主界面去掉历史/统计/工程概念，只给仓库员工做自动测量。

## 8. 给老板/现场能讲清楚的版本

PackVision 不是一个“拍照估尺寸”的玩具。它应该成为海外汽车备件仓库的本地测量工作站：员工扫码后放件，系统调用 Astra Pro 深度相机自动测量，保存单号、图片、深度证据、标注图、测量次数和误差报告。普通箱自动通过，异形件、反光件、透明件、低置信结果自动进入复核。手机照片只做临时兜底，真实尺寸以深度相机和现场真值验证为准。

当前方向正确，但下一步必须从“能测”升级到“自动、可解释、可追溯、可复核”。这就是和 GitHub 高星项目相比最应该补的差距。
