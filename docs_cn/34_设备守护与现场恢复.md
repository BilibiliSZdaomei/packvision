# 设备守护与现场恢复

PackVision 新增轻量设备 watchdog，用来在相机到货后监控深度相机链路是否适合现场试运行。

## 解决什么问题

- 仓库人员不需要理解 OpenNI、驱动、运行库、采集后端这些工程概念。
- 系统会把“没插相机”“实时流卡住”“正在使用模拟兜底”“运行库缺失”等状态转成可执行恢复动作。
- 网页工作台、工位快照和现场支持包都能看到同一份设备健康判断。

## 接口

```text
GET /api/device/watchdog
```

核心字段：

- `status`：例如 `live_camera_active`、`no_camera_detected`、`simulation_fallback`、`live_stale`。
- `severity`：`ok`、`warning`、`critical`。
- `safe_to_record_live`：是否可以把实时结果作为正式发货尺寸记录。
- `dry_run_record_available`：是否可用于无硬件干跑或演示记录。
- `photo_fallback_available`：照片兜底是否可用。
- `signals`：OpenNI 设备数、实时流状态、FPS、更新时间、模拟兜底等。
- `issues`：设备问题列表。
- `recovery_steps`：现场恢复步骤。

## 现场判断

| 状态 | 含义 | 现场动作 |
| --- | --- | --- |
| `live_camera_active` | 真实相机实时流工作中 | 可以持续测量，稳定后记录。 |
| `camera_detected_idle` | 相机已被识别但实时流未启动 | 点击继续实时，观察画面稳定性。 |
| `simulation_fallback` | 正在用模拟数据兜底 | 只适合演示，不适合作为发货尺寸。 |
| `no_camera_detected` | 运行库可用但没看到相机 | 检查 USB 数据线、供电、扩展坞，再开上位机。 |
| `live_stale` | 实时流长时间未更新 | 暂停/继续实时，重复出现就重新插线并导出支持包。 |
| `runtime_not_ready` | OpenNI 或采集后端不可用 | 重新检查驱动和 `D:\app\orbbec-astra-pro`。 |

## 与上位机软件的关系

上位机软件仍然是第一验机工具：

```text
D:\app\orbbec-astra-pro\启动上位机.bat
```

现场顺序：

1. 插相机。
2. 打开上位机，确认 Color/Depth/IR 有画面。
3. 回到 PackVision，运行采集探测。
4. 看设备守护状态。
5. 只有 `safe_to_record_live=true` 时，才把实时结果当作正式尺寸记录。
