# 专业级 DWS 工位 UI 标准

## 对标结论

对标商业尺寸采集、称重、扫码系统后，专业软件一般不是“一个表单 + 一个结果图”，而是一个持续工作的工位控制台。

典型能力组合：

- 条码/单号是业务主键。
- 尺寸、重量、体积重、计费重在同一屏闭环。
- 相机/传感器状态持续监控。
- 图片、深度图、点云或截图作为证据留存。
- 异常、低置信、材质风险进入复核。
- 历史和 WMS/API 同步可追溯。

参考方向：

- DIMS-it：强调尺寸、重量、照片和 API 工作流。
- Cargo Spectre：强调货物尺寸、重量、照片证据和仓库工作流。
- Rice Lake iDimension：强调自动尺寸、重量、条码和图像捕获。
- SICK DWS：强调 Dimensioning、Weighing、Scanning 的一体化。
- Cubiscan：强调尺寸重量系统和仓库/物流落地。

## PackVision UI 原则

1. 首屏必须像设备控制台，而不是普通网页。
2. 相机默认实时运行，按钮只负责记录稳定结果。
3. 工位状态、当前单号、计费重、质检结论必须常驻。
4. 没有标注图时，结果区显示深度证据面板，不再显示“上传照片后开始”。
5. 体积重规则不能藏在后台，必须让仓库主管能看懂并追溯。
6. 手动框选、工程设置、标定等能力隐藏在抽屉或工程页，不能打扰仓库操作员。

## 本轮已完成

- 新增顶部工位状态条：实时状态、当前单号、计费重、质检结论。
- 深度相机结果没有照片时，结果区显示 Astra Pro 深度证据面板。
- 保留实时采集监控：状态、帧数、稳定帧、模拟/硬件状态、FPS、运行时长、测量次数、采集后端。
- 保留重量监控：实重、体积重规则、体积重、计费重、计费来源。
- UI 在窄屏下会折叠，不再让重量监控挤出左栏。
- 工位成熟度评分改为“能力覆盖 + 现场闸口扣分”：即使尺寸、称重、扫码、证据、接口模块都存在，只要真实相机未验证、电子秤未接入、单号/WMS 绑定缺口或设备 watchdog 异常，首屏分数也会下降并显示相应等级。

## 工位成熟度口径

`/api/station/snapshot` 中的 `professional_score` 不再只看模块是否存在：

| 字段 | 含义 |
| --- | --- |
| `capability_percent` | 尺寸、称重、扫码、证据、接口、设备健康这 6 类能力的覆盖分。 |
| `percent` | 扣除现场闸口后的真实成熟度，UI 默认显示这个分数。 |
| `gate_penalties` | 扣分原因，例如真实硬件未验证、电子秤未接入、WMS 未配置、设备 watchdog 异常。 |
| `level` | `pre_hardware_ready`、`field_trial_limited`、`industrial_pilot_ready` 等现场等级。 |

这样做的目的很简单：**模拟链路可以证明业务闭环，但不能冒充真实生产验收。**

## 下一步标准

- 到货后用真实 Astra Pro 画面替代模拟深度证据。
- 接入电子秤后，实重从设备自动填入。
- 单号接口打通后，自动带出客户/国家/承运商体积重规则。
- 在数据中心增加主管视角：每日件数、异常率、复核关闭率、计费重汇总。
