# 工业级架构评估与中型升级方案

## 结论

PackVision 当前架构不建议推倒重来。现有结构属于“本地优先模块化单体”：

- FastAPI 负责本机 API 和静态 UI。
- `packvision/services/*` 已经按能力拆分：测量、深度相机、实时流、历史、统计、复核、部署、AI 插件。
- SQLite 适合海外仓单机开箱即用和 100MB 内交付包。
- 前端是轻量静态页面，普通仓库电脑也能带动。

但如果目标是专业成品软件，当前还缺一个核心层：**Station Orchestrator 工位编排层**。商业 DWS 软件看起来专业，不只是因为界面漂亮，而是因为它把尺寸、称重、扫码、证据、接口同步都统一到同一个工位状态里。

同时，工作台主流程必须明确为：**连接相机后持续实时监控，系统自动测量，操作员只在稳定后点击记录**。上传照片不能再被设计成主流程，只能作为没有硬件、现场离线复核或历史纠错时的兜底入口。

## 对标学习

参考的优秀商业方向：

- DIMS-it：强调尺寸、重量、照片和 API 流程。
- Cargo Spectre：强调货物尺寸、重量、照片证据和仓库工作流。
- Rice Lake iDimension：强调自动尺寸、重量、条码和图像捕获。
- SICK DWS：强调 Dimensioning、Weighing、Scanning 一体化。
- Cubiscan：强调仓储物流场景中的尺寸重量系统。

它们的共同点是 DWS 闭环：

```text
Dimensioning 尺寸
Weighing 称重
Scanning 扫码
Evidence 证据
Integration 接口同步
```

## 当前差距

| 项目 | 当前状态 | 工业级差距 |
| --- | --- | --- |
| 尺寸采集 | 已有图片/深度/实时流 | 还需要真实硬件连续验证和 watchdog |
| 称重 | 已支持手动实重和体积重 | 还缺电子秤 USB/串口/HID 适配 |
| 扫码 | 支持手工、扫码文本、条码图 | 还缺 WMS 单号查询和自动规则带出 |
| 证据 | 标注图、点云证据已开始 | 还需统一证据包和异常回放 |
| 集成 | 本地 API、CSV、日志已具备 | 还缺 WMS/TMS 推送、失败重试队列 |
| 权限 | 暂无 | 主管、操作员、工程师权限需要拆分 |

## 本轮中型升级

新增 `packvision/services/station.py`，形成工位编排层。

新增 API：

```text
GET /api/station/snapshot
```

这个接口输出：

- 当前工位状态：等待放件、测量中、稳定可记录、异常、暂停。
- DWS 能力状态：尺寸、称重、扫码、证据、接口。
- 当前候选尺寸：来自实时深度流。
- 最新历史记录：最近一次保存的单号、计费重、测量方式。
- 工业级缺口：硬件验证、电子秤、WMS、异常处理。
- 下一步升级轨道：电子秤适配、WMS 推送重试、硬件 watchdog、权限审计、相机标定档案。

前端同步改成多相机监控矩阵：

- 顶部相机：单台 Astra Pro 阶段默认点亮，也是第一阶段主画面。
- 正面相机：后续第二台/第三台相机接入时用于高度、正面轮廓和长条件复核。
- 侧面相机：后续三视图时用于侧向轮廓、异形件外接范围和遮挡复核。
- 当前只有一台相机时，其他画面显示“待接入”，避免误导员工以为系统只有单相机架构。
- 按钮语义改成“记录当前稳定结果”；照片上传按钮改成“照片兜底测量”。

本轮继续把编排层接入 UI 顶部状态条：

- 工位状态来自 `/api/station/snapshot`，不是前端单独猜测。
- 顶部状态条新增“工位编排”，显示 DWS 能力成熟度，例如尺寸、称重、扫码、证据、接口状态。
- 顶部状态条新增“到货验收”，读取 `/api/deployment/readiness`，区分照片兜底可用、驱动预装就绪、硬件可试运行、需处理。
- 现场人员不用打开工程接口，也能知道当前是否适合继续试运行。

## 为什么不是大型重构

大型重构现在风险更高：

- 相机未到货，真实硬件约束还没有完全暴露。
- 海外仓目标电脑配置普通，过早引入复杂前端/队列/数据库会增加部署风险。
- 当前模块化 service 层已经能支撑继续拆分。

正确路线是中型升级：

1. 保留本地单体，保证开箱即用。
2. 补工位编排层，让 UI 和业务状态不再散落在前端。
3. 后续设备到位后，新增 device adapter，而不是推翻 API。
4. WMS/TMS 接入时增加 outbox/retry queue，而不是让测量流程直接依赖网络。

## 下一阶段目标

### P0：硬件到货前

- `/api/station/snapshot` 和 `/api/deployment/readiness` 接入 UI 工位状态条。
- 工作台首屏固定显示顶部/正面/侧面多相机监控矩阵。
- 电子秤 adapter 接口设计：USB HID、RS232、手动兜底。
- WMS/TMS outbox 表设计：待推送、已推送、失败、重试次数。
- 异常状态标准化：相机断开、深度噪声、无单号、未称重、低置信。

### P1：Astra Pro 到货后

- 接入真实帧率、序列号、相机温度/连接状态。
- 保存真实深度证据、点云证据和相机内参。
- 标准纸箱、长条件、异形件、反光/黑色/透明材质全流程误差测试。

### P2：工业部署前

- 电子秤自动取实重。
- 单号查询带出客户、国家、承运商、体积重规则。
- WMS/TMS 推送失败重试。
- 操作员/主管/工程师权限拆分。
- 数据中心增加主管报表。
