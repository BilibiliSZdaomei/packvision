# 后台调用日志与测量次数统计

本轮新增后台使用统计，用来回答两个问题：

- 软件到底被调用了多少次。
- 真正发生了多少次测量，后续可以用于日报、周报、月报和项目落地汇报。

## 数据保存位置

使用日志和测量历史共用同一个 SQLite 数据库，但分表保存：

- 开发运行：`D:\Documents\包装尺寸检测\data\packvision.sqlite3`
- 打包 EXE 后：`%LOCALAPPDATA%\PackVision\packvision.sqlite3`

新增表：`usage_events`

每次调用 `/api/*` 接口都会记录一条日志，但 `/api/usage/*` 自己不会被记录，避免“查看统计”把统计次数刷高。

## 已记录字段

- `event_id`：日志 ID。
- `created_at`：UTC 时间戳。
- `endpoint`：调用的接口路径。
- `method`：HTTP 方法。
- `status_code`：接口返回状态码。
- `success`：是否成功。
- `duration_ms`：接口耗时。
- `is_measurement`：是否属于测量调用。
- `order_id` / `measurement_id` / `measurement_source`：预留追溯字段。
- `error_message`：异常信息。

## 测量次数口径

`measurement_calls` 统计下面这些接口：

- `/api/measure`
- `/api/depth/demo-object`
- `/api/depth/demo-object/save`
- `/api/depth/measure-roi`
- `/api/depth/measure-object`

也就是说，查看历史、健康检查、深度质量检查、扫码识别等接口会进入总调用次数，但不会算作测量次数。

## 汇报接口

### 总览

`GET /api/usage/summary`

返回：

- `total_calls`：总调用次数。
- `successful_calls`：成功次数。
- `failed_calls`：失败次数。
- `measurement_calls`：测量次数。
- `by_endpoint`：按接口分组的调用次数。
- `by_day`：按日期分组的调用次数和测量次数。

可选参数：

- `endpoint`
- `date_from`
- `date_to`

示例：

```text
GET /api/usage/summary?date_from=2026-05-01&date_to=2026-05-31
```

### 明细

`GET /api/usage/events?limit=100`

用于查看最近调用日志。

### CSV 导出

`GET /api/usage/export.csv`

可以直接用 WPS / Excel 打开。月报时建议按时间范围导出：

```text
GET /api/usage/export.csv?date_from=2026-05-01&date_to=2026-05-31
```
