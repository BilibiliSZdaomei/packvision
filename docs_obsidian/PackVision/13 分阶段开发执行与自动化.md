# 分阶段开发执行与自动化

> [!summary] 核心
> PackVision 后续开发不靠临场发挥，而是按阶段队列推进：每步小而完整，测试通过，文档同步，提交推送；难以抉择就开 `codex/` 分支。

## 当前自动化

Codex 自动化：

```text
packvision
```

状态：

```text
ACTIVE
```

执行逻辑：

1. 看当前分支和 git 状态。
2. 按路线图选择一个最小可交付任务。
3. 同步代码、测试、中文文档。
4. 运行测试。
5. 必要时打包 EXE 和海外仓交付包。
6. 提交并推送 GitHub。
7. 分歧项开 `codex/` 分支。

## 本地开发循环

普通验证：

```powershell
PowerShell -ExecutionPolicy Bypass -File "D:\Documents\包装尺寸检测\scripts\dev_cycle.ps1"
```

带交付包验证：

PowerShell -ExecutionPolicy Bypass -File "D:\Documents\包装尺寸检测\scripts\dev_cycle.ps1" -BuildPackage

## 分支策略

| 分支 | 用途 |
| --- | --- |
| `codex/astra-pro-depth-camera` | 当前稳定开发主线 |
| `codex/packvision-ui-auto-workstation` | UI 自动化和工位模式探索 |
| `codex/packvision-review-sample-pool` | 复核样本池和真值模板 |
| `codex/packvision-ai-plugin-spike` | YOLO/分割/单目深度插件探索 |
| `codex/packvision-multiview-extrinsics` | 两台/三台深度相机外参和融合 |

## 每轮验收

- `pytest -q` 通过。
- 若影响现场交付，压缩包小于 100 MB。
- 文档更新到 `docs_cn` 和 Obsidian。
- 结果可追溯到 commit。

## 下一步判断

优先做 **工业现场 UI 自动化**。原因：即使深度相机还没到，仓库员工最终也不应该选择模式和参数；UI 自动化会直接降低培训成本。

随后做 **真值模板与复核样本池**。原因：这决定后续 AI 插件和精度优化有没有数据基础。
