# PackVision 对标路线图

> [!summary] 一句话
> PackVision 的路线不是做一个通用视觉库，而是做一个汽车备件仓库能直接用的本地测量工作台：扫码、放件、自动测量、保存历史、导出汇报、异常复核。

## 当前定位

PackVision 应该分成四层：

1. **轻量图片版**：普通 Windows 电脑可跑，用手机照片/上传图片完成估算、单号追溯和历史记录。
2. **Astra Pro 深度相机版**：用深度帧、内参、质量门控做真实三维测量。
3. **多相机三视图版**：未来支持 top/front/side 多视角，适合长条件和大件。
4. **AI 插件版**：YOLO、分割、单目深度只作为增强插件，不塞进基础包。

## 已经做到

- 支持顶部图、侧面图、手动框选、ArUco、焦距/距离估算。
- 支持单号、扫码枪文本、条码图片识别。
- 支持历史记录、CSV 导出、后台调用次数和测量次数统计。
- 支持 Astra Pro 深度相机状态检查、内参归一化、深度 ROI、异形件 mask、长条件主轴、深度质量门控。
- 支持未来多相机角色和融合接口。
- 支持中英乌语言和多主题。

## 还没做到

- Astra Pro 真实硬件还没插机验证。
- 没有真实仓库样本库和人工真值基准。
- UI 还要继续减少选择项，仓库员工最好只扫单号和点测量。
- 还没有完整安装器、驱动检查器、日志打包和远程排错流程。
- AI 模型还没有插件化接口和版本管理。
- 多相机外参、支架、同步和现场验收还没有跑通。

## 对标项目

| 项目 | 学什么 | PackVision 要避免什么 |
| --- | --- | --- |
| [[OpenCV]] | 相机标定、几何、轮廓、二维码、ArUco。 | 不要自己重复造底层视觉轮子。 |
| [[Ultralytics YOLO]] | 检测、分割、OBB、模型导出和推理封装。 | 不要在没有样本库时盲目承诺 AI 精度。 |
| [[Segment Anything]] | 人工复核时快速贴边。 | 不要把重模型塞进基础 EXE。 |
| [[Depth Anything V2]] | 手机照片相对深度辅助。 | 不要把单目深度说成毫米级真实测量。 |
| [[Open3D]] | 点云处理、多视图配准、3D 调试。 | 不要只看 2D 框，忽略深度质量。 |
| [[RealSense SDK]] | 深度相机设备管理和 viewer 体验。 | 不要把设备错误暴露成开发者异常。 |
| [[CVAT]] / [[Label Studio]] | 标注、复核、数据集闭环。 | 不要让失败样本沉没在历史记录里。 |

## 开发优先级

1. **相机到货验收**：先证明真实 Astra Pro 可以稳定输出深度帧和内参。
2. **部署体检**：让新电脑知道缺驱动、缺运行时、相机被占用还是 USB 不稳定。
3. **UI 自动化**：默认自动判断普通包装、长条件、异形件、异常材质。
4. **真实样本库**：把每次测量和人工真值保存下来。
5. **复核样本池**：低置信、人工改框、材质异常、失败重拍都进入复核。
6. **AI 插件接口**：先做接口和目录，再接 YOLO/分割/单目深度。
7. **三视图测量**：从两台相机开始，逐步扩展到三台。

## 自我要求

- 每次新增能力都要同步 API、UI、测试、中文文档。
- 对仓库员工隐藏复杂参数，对管理员保留高级设置。
- 基础包保持轻量；重模型和更高端相机都走插件/后端扩展。
- 凡是未硬件验证、模拟结果、低置信估算，都要在界面和接口里说清楚。
