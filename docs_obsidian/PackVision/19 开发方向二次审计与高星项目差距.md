# 开发方向二次审计与高星项目差距

> [!summary] 结论
> PackVision 的方向没有走偏：真实落地应以 Astra Pro 深度相机、相机内参、深度质量门控、历史追溯和真值复核为主线。  
> 但现在最大的风险是：把“中心 ROI + 模拟深度帧”误认为“自动工业测量”。下一步必须转向自动分割、点云 OBB、真实内参和样本闭环。

## 本轮已完成的纠偏

2026-05-28 已先落地一版最小可用改动：

- `/api/depth/measure-capture` 无 ROI 时先用深度帧自动找前景组件，输出 `auto_depth_foreground`。
- 无法判断前景时才回退到 `auto_center_default`，并写明原因。
- 测量后默认保存深度证据：下采样点云 `.npz` 和深度预览 `.png`。
- 结果中新增 `depth_evidence`，复核样本池可携带 `depth_point_cloud` 链接。
- `/api/depth/measure-capture` 计入后台测量次数。

> [!warning] 还不能过度承诺
> 这不是完整工业点云算法，只是从“中心 ROI 兜底”升级到“深度前景自动测量首版”。后续仍要补真实 Astra Pro 内参链、点云 OBB、现场真值样本和多相机外参验证。

## 主要遗漏

### 1. 自动测量不够自动

当前没有 ROI 时使用中心作业区，这是临时兜底，不是工业级自动识别。仓库员工不应该选框或选类型，系统应自动完成：

- 深度前景提取。
- 桌面/背景去除。
- 最大稳定物体组件筛选。
- 普通箱、长条、异形、软包、反光/透明/黑色风险判断。
- 低置信结果进入复核。

### 2. 真实相机参数链路不完整

PackVision 已能归一化 `camera_info`，但还缺真实 Astra Pro 运行时链路：

- 设备序列号。
- SDK/驱动版本。
- `camera_info` 或 `get_camera_params` 来源。
- 深度单位和 stream profile。
- 每次测量绑定的相机元数据。

这会影响误差追溯和老板汇报时的可信度。

### 3. 点云证据不足

厂商资料强调点云和 PCD，但项目现在主要保存测量结果、图片和标注图。后续应保存：

- 下采样点云 `NPZ` 或 `PCD`。
- 深度质量图。
- mask/ROI 图。
- OBB 预览图。
- 点云测量调试信息。

### 4. 厂商棋盘格应该成为 Astra Pro 工程验收主入口

A4 ArUco 卡仍有价值，但它适合手机照片兜底比例尺，不应作为 Astra Pro 主标定逻辑。Astra Pro 应优先：

- 厂商工具。
- OrbbecViewer。
- OpenNI/ROS 输出的内参。
- 厂商棋盘格和工程验收流程。

### 5. 复核样本池还没变成训练数据资产

当前已有复核样本池，但还需要导出成训练/标注生态能吃的格式：

- COCO。
- YOLO。
- OBB。
- CSV 真值表。
- 原图、标注图、深度样本、点云样本。

## 高星项目对标

| 项目 | 学习点 | PackVision 差距 |
| --- | --- | --- |
| [OpenCV](https://github.com/opencv/opencv) | 标定、畸变、几何、轮廓、ArUco | 我们还缺系统化失败诊断和畸变/透视处理。 |
| [Ultralytics YOLO](https://github.com/ultralytics/ultralytics) | 检测、分割、OBB、训练导出 | 我们还没有真实包装/异形件数据集和模型版本管理。 |
| [Segment Anything](https://github.com/facebookresearch/segment-anything) | 人工复核时快速贴边 | 我们手动修正还偏粗，只能框选/轮廓调整。 |
| [Open3D](https://github.com/isl-org/Open3D) | RGBD、点云、OBB、配准、可视化 | 我们缺点云工件保存和专业点云调试界面。 |
| [RealSense SDK](https://github.com/realsenseai/librealsense) | 设备状态、流管理、frame pipeline、viewer | 我们还不是 SDK 级工具链，需要学习诊断体验。 |
| [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2) | 手机照片相对深度先验 | 不能当毫米级真实尺寸来源。 |
| [CVAT](https://github.com/cvat-ai/cvat) / [Label Studio](https://github.com/HumanSignal/label-studio) | 标注、复核、数据治理 | 我们需要把失败样本变成训练资产。 |
| [labelCloud](https://github.com/ch-sa/labelCloud) | 点云 3D 标注和 OBB 思路 | 异形件阶段应保留点云样本，方便 3D 复核。 |

## 下一轮开发优先级

1. `/api/depth/measure-capture` 从中心 ROI 改成自动找物体。
2. 补全真实 Astra Pro 参数链：`camera_info`、`get_camera_params`、序列号、SDK、stream profile。
3. 保存点云证据：下采样点云、深度质量图、mask、OBB 预览。
4. UI 改成“扫码工作站”：历史、统计、标定、工程参数移出主工作台。
5. 复核样本池导出 COCO/YOLO/OBB/CSV。
6. 多相机只在真实支架和外参验证后声明可用。

## 给老板能讲的话

PackVision 不是拍照估尺寸的玩具，而是海外汽车备件仓库的本地测量工作站。员工扫码后放件，系统用 Astra Pro 深度相机自动测量，保存单号、图片、深度证据、标注图、测量次数和误差报告。普通箱自动通过，异形件、反光件、透明件、低置信结果自动进入复核。手机照片只做临时兜底，真实尺寸以深度相机和现场真值验证为准。
